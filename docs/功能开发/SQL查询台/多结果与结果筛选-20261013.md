# SQL 查询台：多结果与本地筛选

基于 master `f6b59763a43a8011be0217fefea39a3344372379`。本轮不改写历史，不修改数据库表结构、数据库账号或数据权限边界。

## 用户行为

- 执行全部或包含多条语句的选区后，按“语句序号 · 结果序号”切换本批已返回的各结果集，默认仍展示最后一个已返回结果。
- 同一脚本在同一数据库连接中依次执行，保留 USE / 会话变量依赖。不是在前端逐条发请求。
- 语句失败时保留已完整读取的前面结果，停止执行后续语句。逐语句记录明确区分成功、失败、达到上限、未执行，并显示耗时、行数、结果数、更新计数和 SQL 错误代码。
- 零行 SELECT 仍是一个可切换的结果集；SET 等无表格结果的语句单独记录，不伪造 SELECT 结果。
- 当前结果支持不区分大小写的文本筛选，包含 NULL、数字、布尔值及 JSON 文本。筛选不会发请求、不改变 SQL、不改变原始返回快照。
- 切换结果会清空筛选并回到第一页。复制当前页、复制筛选结果、双击单元格详情及 XLSX 导出均针对当前选中的结果；筛选导出需要确认范围。
- 在导出确认期间切换结果或改变筛选，会放弃该次旧导出，避免误导出另一个结果。
- 执行日志仅保留 SQL 快照和逐语句统计，不把查询数据行写入浏览器历史。

## 前后端协议与限制

新增 `POST /workstation/sql-query/execute-batch`，请求字段仍是 sql、limit、timeoutSeconds。返回 data 使用 protocolVersion=1、status、statements、executionTime、totalRows、maxTotalRows、maxResults。每条 statement 包含 index、sql、status、executionTime、results、updateCounts、message、sqlState、errorCode。

外层 ResultHolder.success 表示已获得一份批执行报告，并不表示所有 SQL 成功；必须检查 data.status 和逐语句 status。连接建立、参数校验或权限检查等未获得报告的失败仍用原 ResultHolder.error 返回。

旧 `/execute` 及原 SqlQueryResult DTO 保持不变，避免破坏旧客户端。新页面使用新增接口，出错不会自动回退重放旧接口。

**本轮需要工作台前端与后端一起更新，不能只替换前端文件。**

固定保护上限：每批最多 20 条语句、100,000 个脚本字符、20 个 JDBC 结果（包含更新计数）、所有结果合计最多 5,000 行。单结果仍受用户设置的行数限制。达到批级返回上限后，未读取的结果不再读取，尚未开始的后续语句标为未执行；需要拆分或缩小查询范围。已经开始执行的存储过程不能据此认定被撤销。

新接口的 timeoutSeconds 是整批 JDBC 执行预算，不含建立连接。每条语句使用剩余预算设置 JDBC 超时，并在语句与结果读取边界检查总时间。驱动对阻塞读取/网络超时的支持不同，这不是整个 HTTP 请求的精确硬截止时间。

只限制返回行数和结果个数，并非完整的返回字节数限制；大字段、只读数据库授权、项目数据隔离、真正取消运行中的 SQL、参数模板、编辑器升级均不在本轮实现范围。关闭结果仍不会取消数据库查询。

### 联调检查（请使用开发/测试数据库）

1. `SET @sql_query_check = 7; SELECT @sql_query_check AS value; SELECT 'second' AS value;`：两个可切换结果，SET 单独记为成功。
2. `SELECT 1 AS value; SELECT * FROM __sql_query_nonexistent_table__; SELECT 3 AS value;`：保留第一个结果，第二条失败，第三条未执行。
3. `SELECT 1 AS value WHERE 1=0; SELECT 2 AS value;`：零行结果仍可选择。
4. 运行慢查询期间切换草稿：迟到结果不覆盖当前窗口；执行记录仍对应原 SQL。
5. 筛选、清空、切换结果、分页和复制；导出确认时切换结果或修改筛选，不导出错误快照。
6. 使用达到批级预算的脚本：检查 LIMIT 与 SKIPPED 标记；不要把它误认为查询已经完整执行。
