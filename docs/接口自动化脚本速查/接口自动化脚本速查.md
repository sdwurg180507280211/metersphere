# 接口自动化脚本速查（Groovy + BeanShell，MeterSphere v2.10-lts）

> 适用：接口自动化场景「脚本」步骤（JSR223Processor）。运行时由 JMeter 的
> `ScriptEngineManager` 加载 Groovy 引擎（groovy-jsr223 3.0.11），跑在 **Java 17 JVM** 内。
> 变量注入清单直接取自 `framework/sdk-parent/jmeter/.../util/JSR223TestElement.java:127-150`。

## 一、平台自动注入的上下文变量（不用声明，直接可用）

| 变量 | 类型 | 常用方法 |
|---|---|---|
| `vars` | JMeterVariables | `vars.get("k")` / `vars.put("k","v")` / `vars.putObject("k",obj)` / `vars.getObject("k")` |
| `log` | 日志器(Logger) | `log.info(...)` / `log.warn(...)` / `log.error(...)` |
| `prev` | SampleResult（上一步结果） | `prev.getResponseDataAsString()` / `prev.getResponseCode()` / `prev.getResponseHeaders()` / `prev.getResponseMessage()` |
| `ctx` | JMeterContext | `ctx.getPreviousResult()` / `ctx.getCurrentSampler()` |
| `props` | 全局 JMeter 属性(Properties) | `props.get("propName")` |
| `sampler` | 当前 Sampler 对象 | — |
| `OUT` | System.out（PrintStream） | `OUT.println(...)` |
| `Label` / `FileName` / `Parameters` / `args` | 脚本参数相关 | `Parameters`=传入字符串，`args`=切分后数组 |

## 二、最常用的写法

### 1. 读写测试变量（最高频）
```groovy
def token = vars.get("token")     // 取字符串变量
vars.put("newVar", "value")       // 存字符串变量
vars.putObject("user", userObj)   // 存对象（必须用 putObject）
def o = vars.getObject("user")    // 取对象
```
⚠️ `vars.put` **只能存字符串**；存对象必须用 `putObject`/`getObject`，否则下游取不到。

### 2. 读上一步响应并解析 JSON（Groovy 自带 JsonSlurper，无需 jar）
```groovy
import groovy.json.JsonSlurper
def resp = prev.getResponseDataAsString()
def json = new JsonSlurper().parseText(resp)
def id = json.data.id
vars.put("id", id.toString())
log.info("解析到 id = " + id)
```

### 3. 自定义断言（脚本里抛异常 = 该步骤失败）
```groovy
if (prev.getResponseCode() != "200") {
    throw new Exception("响应码非200: " + prev.getResponseCode())
}
if (!prev.getResponseDataAsString().contains("success")) {
    throw new Exception("响应体未包含 success")
}
```

### 4. 字符串 / 集合处理（Groovy 语法糖）
```groovy
def s = "  hello  ".trim()
def list = [1, 2, 3]
def mapped = list.collect { it * 2 }   // [2, 4, 6]
def joined = list.join(",")            // "1,2,3"
def upper = "abc".toUpperCase()        // "ABC"
```

### 5. 调用自己上传的 jar 里的类
```groovy
import com.mycompany.MyUtil
def r = MyUtil.calc(vars.get("input"))
vars.put("result", r.toString())
```
前提：jar 必须用 **Java ≤ 17** 编译，并在「项目设置 → jar 包管理」上传（运行时落在
`/opt/metersphere/data/api-folder/jar/`）。

### 6. 随机值 / 时间戳
```groovy
vars.put("ts", System.currentTimeMillis().toString())
def rand = new Random().nextInt(1000)
```

## 三、Groovy 语法要点（对比 Java）

- 类型可省略，用 `def`：`def x = 1` ≈ `int x = 1`
- 语句末尾分号可选
- 字符串插值（双引号）：`"id=${id}"`
- 闭包：`list.each { println it }`
- 自带 `JsonSlurper` / `XmlSlurper`，解析 JSON/XML 不用额外 jar
- 单参数方法调用可省略括号

## 四、避坑清单

1. Groovy 3.0.11 语法兼容 Java 8+，但整个平台跑在 JVM17，**引用的自定义 jar 必须 ≤ Java 17 字节码**（Java 21 的 jar 会 `UnsupportedClassVersionError`）。
2. `vars.put` 只能放字符串，对象务必 `putObject`。
3. 脚本 `import` 的类来自「jar 包管理」上传的 jar，非系统 classpath。
4. 断言失败用 `throw new Exception("原因")`，MeterSphere 会标该步骤失败。
5. 禁止 `System.exit()` 之类会搞垮 JVM 的调用。
6. 四种脚本语言：beanshell 2.0b6 / groovy 3.0.11 / python(Jython) 2.7 / javascript(Rhino) ES5.1；
   优先用 Groovy（功能最全、可编译加速）。Python 是 2.x 语法、JS 只到 ES5，别用新版语法。

## 五、实战场景示例（均用 JDK 自带 API，无需上传 jar）

### 1. 加解密 / 签名（java.security.MessageDigest + java.util.Base64）
```groovy
import java.security.MessageDigest
import java.util.Base64

// 通用：字节数组 → 十六进制串
def hex(byte[] d) {
    return d.collect { String.format("%02x", it & 0xff) }.join("")
}

// MD5（常用于签名/校验）
def md5 = hex(MessageDigest.getInstance("MD5").digest(
        ("hello" + vars.get("token")).getBytes("UTF-8")))
vars.put("sign", md5)

// SHA-256
def sha = hex(MessageDigest.getInstance("SHA-256").digest(
        "data".getBytes("UTF-8")))
vars.put("sha", sha)

// Base64 编解码（Java 8+）
def b64 = Base64.getEncoder().encodeToString("明文".getBytes("UTF-8"))
vars.put("b64", b64)
def decoded = new String(Base64.getDecoder().decode(b64), "UTF-8")
```
> 提示：`MessageDigest` / `Base64` 都是 JDK 自带，跑在 Java 17 上直接可用。

### 2. 文件读写（java.nio.file.Files，Java 11+ 一行搞定）
```groovy
import java.nio.file.Files
import java.nio.file.Paths
import java.nio.charset.StandardCharsets

// 读文本
def text = Files.readString(Paths.get("/opt/metersphere/data/tmp/input.txt"), StandardCharsets.UTF_8)
log.info("读到: " + text)

// 读字节
byte[] data = Files.readAllBytes(Paths.get("/opt/metersphere/data/tmp/a.bin"))

// 写文本
Files.writeString(Paths.get("/opt/metersphere/data/tmp/out.txt"), "内容", StandardCharsets.UTF_8)

// 逐行处理
Files.readAllLines(Paths.get("/opt/metersphere/data/tmp/list.txt"), StandardCharsets.UTF_8).each { line ->
    log.info("行: " + line)
}
```
> 注意：路径必须对**运行脚本的 JVM 进程**可见。本地模式是 api-test 进程；资源池/K8s 模式是 ms-node 容器，路径要在容器内存在。优先用 `/opt/metersphere/data/` 下的绝对路径。

### 3. 循环调接口并串变量（java.net.http.HttpClient，Java 11+ 自带）
```groovy
import java.net.http.HttpClient
import java.net.http.HttpRequest
import java.net.http.HttpResponse
import java.net.URI
import groovy.json.JsonSlurper

def client = HttpClient.newHttpClient()
def ids = vars.get("idList").split(",")   // 从变量读一组 id
def names = []

ids.each { id ->
    def req = HttpRequest.newBuilder()
        .uri(URI.create("http://api.example.com/items/${id}"))
        .header("Authorization", "Bearer " + vars.get("token"))
        .GET()
        .build()
    def resp = client.send(req, HttpResponse.BodyHandlers.ofString())
    if (resp.statusCode() != 200) {
        throw new Exception("调接口失败 id=${id} code=${resp.statusCode()}")
    }
    def json = new JsonSlurper().parseText(resp.body())
    names << json.name
    log.info("id=${id} -> name=${json.name}")
}
vars.put("names", names.join(","))   // 结果回写变量，供下游步骤用
```
> 说明：这是在「脚本」步骤里**用代码直接发 HTTP 并循环**，适合做数据准备/批量探查。
> 若只是想"对一组参数重复跑同一个接口请求"，更推荐在场景里用「循环控制器 / 批量」步骤，
> 而非写在脚本里——脚本方式适合需要自定义拼装/解析逻辑的场景。

## 六、BeanShell 语法要点（与 Groovy 对照）

BeanShell 2.0b6 也是「脚本」步骤的可选语言。它与 Groovy **共享同一套注入变量**（vars/log/prev/ctx…）
和**完全一致的 Java API 调用能力**——区别只在"语言糖"。

### 语法差异速查

| 能力 | Groovy | BeanShell |
|---|---|---|
| 松散类型声明 | `def x = 1` | `x = 1`（也认 `def`） |
| 字符串插值 | `"id=${id}"` | ❌ 不支持，用 `"id=" + id` |
| 列表/Map 字面量 | `[1,2,3]` / `[k:v]` | ❌ 不支持，用 `new ArrayList()` / `new HashMap()` |
| 闭包遍历 | `list.each{...}`、`collect` | ❌ 不支持，用标准 `for`/`while` |
| lambda `->`、方法引用 `::` | 支持（闭包） | ❌ 不支持 |
| `var`/switch 表达式/record/try-with-resources | 部分支持 | ❌ 均不支持（Java 8+ 语言特性） |
| 调任意 Java API | ✅ | ✅ 完全一致 |
| 注入变量 vars/log/prev/ctx | ✅ | ✅ 完全一致 |

### 关键限制（最容易踩）
- ❌ **没有 lambda / 闭包糖**：回调要写匿名类（`new Runnable(){ public void run(){...} }`）或 BeanShell 的 `object()` 闭包。
- ❌ 不支持 Java 8+ 语言特性：`var`、严格泛型、`::`、switch 表达式、record、try-with-resources。泛型建议写裸类型 `List` 而非 `List<String>`。
- ⚠️ 没有列表字面量 `[1,2,3]`，集合必须 `new ArrayList()` 后 `.add()`；数组可用 `String[] a = {"x","y"}`。
- ⚠️ 字符串只能 `+` 拼接，没有 `${}` 插值。
- ✅ `groovy.json.JsonSlurper` 是 classpath 上**已编译的类**，BeanShell 也能 `new` 它解析 JSON；但 BeanShell 下用 `.get("k")` 取字段更稳（Groovy Map 的属性访问在 BeanShell 里不灵）。

### BeanShell 实用示例

```beanshell
// 1. 读写变量（松散类型，不用声明类型）
token = vars.get("token");
vars.put("newVar", "value");
vars.putObject("user", userObj);    // 对象仍需 putObject

// 2. 解析 JSON（复用 classpath 上的 JsonSlurper，用 .get() 取字段）
import groovy.json.JsonSlurper;
resp = prev.getResponseDataAsString();
json = new JsonSlurper().parseText(resp);
id = json.get("data").get("id");
vars.put("id", String.valueOf(id));
print("解析到 id = " + id);          // BeanShell 内置 print 命令

// 3. 断言（抛异常 = 步骤失败，与 Groovy 一致）
if (prev.getResponseCode() != "200") {
    throw new Exception("响应码非200: " + prev.getResponseCode());
}

// 4. MD5 签名（纯 Java API，写法与 Groovy 几乎一样，只是无插值）
import java.security.MessageDigest;
sb = new StringBuffer();
for (byte b : MessageDigest.getInstance("MD5").digest(
        ("hello" + vars.get("token")).getBytes("UTF-8"))) {
    sb.append(String.format("%02x", b & 0xff));
}
vars.put("sign", sb.toString());

// 5. 文件读写 / 循环调接口 / Base64
//    这些全是 Java 标准 API，BeanShell 与 Groovy 写法一致，
//    仅少了字符串插值/闭包糖，循环用标准 for。详见「五、实战场景示例」。
```

> 实践建议：新脚本优先用 **Groovy**（语法糖多、可读性好、可编译加速）；
> BeanShell 仅在历史脚本 / 简单取值场景保留。两者在 MeterSphere 里共享同一套 vars/log/prev 与 Java API。
