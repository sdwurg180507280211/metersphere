## 一、先看结论

入职初期的判断基本成立：MeterSphere 项目确实让工作范围从单纯 Java 后端扩展到了前端、平台设计、部署运维、需求对接和测试领域。

但当前实际发展路径已经和年初设想有明显变化：

- Flowable 仍是重要技术实践，但并没有成为项目唯一主线
- 工作重心逐渐从“做一个工作流能力”转向“持续建设企业内部测试平台”
- 近期更核心的工作是测试计划、INT 测试主流程、需求字段映射、缺陷管理、查询与数据权限
- Jenkins、Docker、环境运维已经成为稳定能力，不再需要作为唯一职业标签

当前更准确的定位是：

> **Java 后端 → 测试平台全栈开发 → 平台需求与技术设计 + DevOps → 质量效能 / 测试平台工程**

这一阶段最大的收获不是某一个技术点，而是开始具备“独立负责平台”的完整视角。

### 3. 2026年8月～9月：测试主流程与平台化阶段

从仓库最近提交可以确认，工作重点已经明显转移到测试计划和 INT 测试流程。

主要内容包括：

#### INT 测试主流程

- 新增并持续完善 INT 测试流程需求规格
- 对齐 INT 流程需求与技术设计
- 明确需求编号与所属系统映射
- 明确全研发需求字段映射
- 补充测试计划创建与办结规则
- 持续根据需求变化更新技术设计

这部分工作说明职责已经不只是“接到需求写代码”，而是在参与：

> 业务规则梳理 → 字段模型 → 流程边界 → 技术设计 → 系统落地

#### 测试跟踪与缺陷管理

- 修复测试计划关联缺陷不显示问题
- 修复高级搜索清理用户组筛选报错
- 持续完善测试计划和缺陷之间的数据关系

#### 工作台与通用能力

- 优化查询结果区域自动展开交互
- 合并查询台优化组件，减少重复包装逻辑
- 修复单服务启动场景下验证码接口缺失问题
- 修复过滤器链顺序不稳定问题

这些工作虽然单个提交不大，但更接近真实企业平台的长期建设：功能、稳定性、数据关系和用户体验需要一起维护。

## 三、对年初职业规划的校准

### 1. Flowable：从“核心方向”调整为“重要技术经历”

年初一度把 Flowable / BPMN 作为主要差异化方向，这个判断现在需要收敛。

实际情况是：

- 缺陷 8 状态流转首先采用状态机方案
- Flowable 7 完成了独立服务、API、设计器和模型库方向的 PoC
- 后续项目主线没有持续围绕 Flowable 单点展开
- 当前业务价值更集中在测试流程、平台能力和系统整合

因此简历和面试中不再表述为：

> “基于 Flowable 实现了当前全部缺陷工作流”

更准确的表达是：

> “完成缺陷状态机流转，并独立搭建 Flowable 7 + BPMN 设计器 PoC，验证流程配置化方案。”

### 2. DevOps：已经是基础能力，不必把自己限定成运维方向

Jenkins、Docker、Nginx、环境管理已经形成实际经验，但当前项目价值明显不止 CI/CD。

更合理的表达：

> DevOps 是测试平台工程能力的一部分，而不是唯一职业方向。

### 3. 测试架构师：保留方向，但先把“平台工程”做扎实

年初文档中多次强调“测试架构师”。这个方向可以保留，但现在不急着给自己贴专家标签。

当前最有价值的能力组合是：

- Java 后端
- Vue 前端联调
- 测试领域业务理解
- 数据权限与查询
- 测试计划 / 缺陷流程
- 平台需求分析与技术设计
- CI/CD 与生产环境维护

这比单独强调某个框架更有竞争力。

## 四、当前真正形成的项目壁垒

### 1. 能独立承担完整链路

已经覆盖：

`需求沟通 → 方案设计 → 前后端开发 → 数据库 → 测试验证 → CI/CD → 部署 → 线上排查`

这类完整项目闭环，是当前 MeterSphere 经历最值得保留的部分。

### 2. 开始从“功能开发”进入“平台设计”

INT 测试流程相关工作已经涉及：

- 流程边界
- 字段定义
- 多系统映射
- 计划生命周期
- 需求与技术设计持续同步

这类经验比“新增一个页面/接口”更适合在后续简历和面试中重点展开。

### 3. 同时理解开发和测试使用场景

长期维护测试平台后，逐步积累了：

- 测试计划
- 缺陷管理
- 测试人员/开发人员权限差异
- 跨项目、跨工作空间查询
- 测试数据统计
- 平台使用体验

这已经属于质量效能平台方向的业务积累。

## 六、后续3个月行动重点

### 1. 项目

优先把 INT 测试主流程做成一条完整、可说明的项目案例：

- 需求背景
- 原系统问题
- 流程与字段模型
- 技术方案
- 核心实现
- 关键问题
- 上线结果

目标不是再堆功能，而是形成一个能在面试中完整讲 15～20 分钟的代表项目。

### 2. 技术

主线控制在三项：

- Java / Spring 后端深度
- 测试平台与质量效能业务
- Docker / Jenkins / Linux 生产实践

Flowable、Kubernetes、前端等按项目需要继续补，不再同时铺太多学习路线。

### 3. 文档

以后个人工作记录建议采用：

```
每月阶段总结
├─ 本月实际完成
├─ 解决的核心问题
├─ 关键技术决策
├─ 可量化结果
├─ 踩坑与修复
└─ 下阶段重点
```

比逐周流水账更容易长期坚持，也更适合转成简历素材。

### 4. 简历

持续只记录已经发生并能解释清楚的内容。

重点优先级：

1. 测试平台独立负责
2. INT 测试主流程与测试计划
3. 缺陷管理、权限、查询等平台能力
4. CI/CD 与环境维护
5. Flowable PoC

不要为了显得技术栈多，把 PoC 写成生产核心实现。
